# 科研实验仓库 Skill

**把实验交给执行者，把科学判断留给负责人。**

适合手下至少有一个能自主执行实验的主体、需要掌控项目却不亲自操作的科研人员：Coding Agent、实验员、受 AI 调度的仪器或机器人都可以参与。

多人协作时，报告、脚本、原始数据和聊天记录常常各在一处。负责人看到一个漂亮数字，却不知道它来自哪次运行、哪版配方，失败是否被删掉，下一个执行者能否接手。本 skill 让 AI 先与你对齐报告和协作契约，再建立能把结论追溯到证据的仓库。

## 你需要决定什么

AI 会先问报告写给谁、哪些图重要、图如何画、目录如何组织、谁能批准实验和整合结果。你会看到具体审批单，包括 `readme2machine/` 的目录和拟定内容，批准后才动工。哈希、文件索引、命令归档等常规整理由 AI 自主处理并说明。

报告是主要入口，机器材料让结果可核验。有效的负结果也能交付；缺材料与假设不成立是不同状态。这个工具不保证实验成功，也不替代领域专家、仪器安全制度或数据访问审批。

## 包含什么

| 路径 | 用途 |
|---|---|
| [SKILL.md](SKILL.md) | 给 AI 的提问、审批、建仓与交付流程 |
| [template/](template/README.md) | 可适配的仓库模板，预置 asset 和机器协作说明 |
| [example/](example/README.md) | 从真实项目筛选、脱敏的 GSM8K GRPO 与 CoD 提示实验 |

示例展示一种经过使用的组织方式。新项目的报告、统计方法、执行工具及目录由其负责人确认，不要求所有学科照搬 LLM 实验。

## 使用

将整个仓库作为名为 `research-experiment-repo` 的 skill 目录放入 Agent 支持的技能路径；保留 template 与 example 的相对位置。也可以直接把 [SKILL.md](SKILL.md) 交给支持读取文件的 AI。

例如：

> 使用 $research-experiment-repo。我要管理材料老化实验，由两名实验员执行。我关心强度随时间变化和失败样品。请先和我对齐报告、图表、目录与权限，提交含 readme2machine 的审批单，批准后再建仓。

安装本身不启动实验。该仓库的模板是普通文件模板，不是 Codex Artifact Template Gallery 制品。

## 方法来源

来自真实 RLVR 实验仓库的报告—复现材料—原始证据组织经验，并针对委托式实验管理泛化。示例只保留 GSM8K 的 GRPO 与 CoD 提示两项及必要对照，具体来源、转换和复现范围见 [example/README.md](example/README.md)。
