# 科研实验仓库 Skill

**把实验交给执行者，把科学判断留给负责人。**

适合手下至少有一个能自主执行实验的主体、需要掌控项目却不亲自操作的科研人员：Coding Agent、实验员、受 AI 调度的仪器或机器人都可以参与。

多人协作时，报告、脚本、原始数据和聊天记录常常各在一处。负责人看到一个漂亮数字，却不知道它来自哪次运行、哪版配方，失败是否被删掉，下一个执行者能否接手。本 skill 让 AI 先与你对齐报告和协作契约，再建立能把结论追溯到证据的仓库。

## 开始前准备

**建议研究人员准备一个自己的 GitHub 账号**，便于保存、分享和协作审核实验记录；也可以选择 Gitee 等偏好平台。仅在本地管理时不需要平台账号。

AI 的第0步会先问：仅本地建仓，还是本地＋远程关联同步？选后者时，AI先检查已有平台、仓库和认证信息，再请你补齐缺项。你可以授权已登录浏览器建仓、自己提供空仓库并配置本地SSH/HTTPS认证，或使用已授权连接器/CLI、个人访问令牌。浏览器建仓与本地Git推送需要分别具备条件。具体凭据名称及权限见 [远程接入说明](references/remote-access.md)；不用在聊天里发送私钥或令牌。

## 你需要决定什么

AI 会先问报告写给谁、哪些图重要、图如何画、目录如何组织、谁能批准实验和整合结果。你会看到具体审批单，包括 `readme2machine/` 的目录和拟定内容，批准后才动工。哈希、文件索引、命令归档等常规整理由 AI 自主处理并说明。

报告是主要入口，机器材料让结果可核验。有效的负结果也能交付；缺材料与假设不成立是不同状态。这个工具不保证实验成功，也不替代领域专家、仪器安全制度或数据访问审批。

## 协作方式可以选择

多智能体可用时，推荐**主代理派发实验并审核，实验子代理执行、保存证据并提交报告**。AI会与你确认这套模式、预算、并发和升级边界，放入审批单后才启用；也支持人类/设备执行，或单AI执行、负责人审核。

执行子代理优先选择能胜任任务的低成本模型。省钱要算上失败重试、返工与实验资源，不能只看token单价。启动实验的子代理通过轮询跟踪运行，可借助脚本读取状态；间隔先与你确认，默认依次等待1、2、4、8、16分钟，随后每30分钟检查一次。正常运行保持安静；异常停止时通知主代理，正常退出后撰写实验报告并请求主代理审核，运行中需要决策时及时上报。

skill负责责任和交付约定，项目级 [协作配置](template/readme2machine/collaboration.md) 负责模型、人员、工具和调度。因此，更换模型或代理框架不会迫使报告和证据规范一起重写。

仓库提交采用固定流程：子代理从最新主分支提交派生工作分支，提交前同步并冻结SHA，主代理审核后用 `git merge --no-ff` 整合。分支名称和执行模型可以配置，继承与合并规则跨任务一致。

## 使用

将整个仓库作为名为 `create-research-experiment-repo` 的 skill 目录放入 Agent 支持的技能路径；保留 template 与 example 的相对位置。也可以直接把 [SKILL.md](SKILL.md) 交给支持读取文件的 AI。首次使用的话，可以直接把仓库链接粘贴进聊天框，然后让AI直接去网上读这个仓库（或者把这个skill安装下来），然后让AI照此工作。

例如：

> 使用 $create-research-experiment-repo。我要管理材料老化实验，由两名实验员执行。我关心强度随时间变化和失败样品。请先和我对齐报告、图表、目录与权限，提交含 readme2machine 的审批单，批准后再建仓。

安装本身不启动实验。该仓库的模板是普通文件模板，不是 Codex Artifact Template Gallery 制品。

## 方法来源

来自真实 RLVR 实验仓库的报告—复现材料—原始证据组织经验，并针对委托式实验管理泛化。示例只保留 GSM8K 的 GRPO 与 CoD 提示两项及必要对照，具体来源、转换和复现范围见 [example/README.md](example/README.md)。
