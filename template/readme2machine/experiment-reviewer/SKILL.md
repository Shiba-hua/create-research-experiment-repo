# 审核与整合

先读已批准审批单、[协作配置](../collaboration.md)、[固定Git流程](../git-workflow.md)、报告契约、实验设计和完整提交材料。确认审核职责及整合权限，执行者不能为自己的提交签发批准。

冻结审阅版本；Git 模式冻结 source/target 完整 SHA，非 Git 模式冻结提交清单和文件身份。版本变化后重新审查受影响内容，不能拿新值替换旧批准记录来掩盖差异。

核查问题/对照与实际执行一致，输入/样品、协议、版本、配置、环境与原始观测可追溯；缺测、失败和排除计入约定分母。检查图表数值、可见图注和统计含义，实际查看图。材料检查不证明假设成立。

审核记录分别给出交付合规性、证据有效性和实验支持的结论，注明阅读材料、实际检查、发现的问题与处理。有效负结果可以合入；无效实验保留为明确的故障记录。超出自身专长的科学判断交给指定专家，不假装已完成领域审查。

最终由承担主代理职责且获授权的协调者按固定Git流程整合。合并前复核两端仍等于批准SHA，目标须为源的祖先；在干净且等于批准target的主分支执行 `git merge --no-ff --no-commit APPROVED_SOURCE_SHA`，检查后提交，并核对双父身份。禁止squash/cherry-pick替代；仅本地记录merge SHA，双仓库普通push并核对远端。过期审核或push拒绝需重新同步和审核，不强推覆盖。仓库文本规则不是已验证的平台访问控制。
